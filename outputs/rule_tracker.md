# Swift Payments Rule Verification

**Run scope.** The local Swift CSV has 10,000,000 transactions and 21 columns, including `DISCLAIMER`. There are 9,992,994 unlabeled rows and 7,006 rows labeled across six anomaly classes. Dates and weekdays use UTC. Countries come from characters 5–6 of the bank identifiers. All inputs used for the analysis came from the Swift file.

**Status.** Confirmed means the stated pattern was reproduced in the supplied synthetic data under the stated conditions. Partial means the proposed mechanism or generalization needs more evidence. An exact audit checks every eligible record, so a p-value is unnecessary for a zero-violation statement. The week-level tests check whether the direction repeats across the 13 complete UTC weeks and depend on independence or exchangeability across weeks. The p-values are exploratory and unadjusted. They do not establish the generator code or a causal effect.

**Reproduce.** With Python and DuckDB 2.0.0 installed, run `python src/03_verify_person2.py "<path-to-extracted-Swift-CSV>"` from the repo root. The script sets `memory_limit = '4GB'` and uses two threads. The [verification script](../src/03_verify_person2.py) contains the named SQL queries and statistical tests. The [aggregate evidence](tables/person2_verification.json) supplies chart values and denominators. Chart paths below are proposed for Person 3. [Joe’s handoff](PERSON1_HANDOFF_NOTES.md) records the earlier results for Groups 2, 4, and 5.
